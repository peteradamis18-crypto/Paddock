# SH-02 Share: phone Photos / share sheet / codec
**Phase / depends on / size / needs Peter:** Phase 5 / SH-01, P0-02 / M / none
## Why
Create a shareable H.264 MP4 and let the phone share it using the browser share sheet or save it for Photos. Paddock does not send messages itself.
## Read first
Read AGENTS.md, CLAUDE.md, docs/COPY-RULES.md, SPEC-v4.md §§1,3,5, docs/vault.md. Existing phone app handlers share (app.js:622), shareSend (613), makeShare (607), paintShare (580), status/make/video routes in Share.Handle (dash/src/share.cs:513), encoder fallback in Share.Render/RunFfmpeg (713,772). Phone code already calls navigator.canShare/share when available and downloads otherwise. tests/phone-test.ps1 and tests/share-test.ps1 exist. No /share/phone route exists; current /share/video serves completed file.
## Build
1. Inspect actual ffmpeg command and encoder fallback. Require codec_name=h264 from ffprobe for every share output; if NVENC output fails, fallback to libx264 veryfast, then verify again. Delete/mark failed any non-H.264 output; never present it as ready.
2. Keep /share/video Range behavior; do not add redundant /share/phone unless testing proves a phone-specific MIME/disposition fix is needed. Existing route is the reuse path. Set video/mp4 and safe attachment filename.
3. In app.js preserve existing makeShare -> sharePoll -> paintShare flow. Web Share API requires secure context and user gesture; use navigator.canShare({files}) then navigator.share in gesture handler. Otherwise provide download link labeled Save; truthful fallback text per copy rules. Do not promise Photos specifically when browser only saves a file.
4. Whole-session share: require explicit selected lap/clip ID. Existing share make accepts a clip/Vault lap ID; do not guess “last lap” from a session ID. If adding session ID support, resolve latest completed lap from recorder data and test exact chosen interval. No direct share while on track; existing Share.Make guard must remain.
5. Extend tests/phone-test.ps1 and share-test.ps1 with mock Web Share available/unavailable, H.264 probing/fallback and interval selection. Guard every section. C# 5; no iRacing writes; copy rules.

## Gate
At least 5 phone checks and 3 codec checks: Web Share called only from user gesture when file sharing is supported; fallback download works without API; displayed fallback is accurate; chosen lap/clip ID reaches /share/make unchanged; on-track make refused. ffprobe codec_name=h264 after normal and fallback encode; non-H.264 output is rejected and not marked done. Numeric ok/FAIL output; Peter fails if iPhone cannot play/share or wrong lap is cut. Compile -NoDeploy.
## User journey
Phone Videos: Make share video, wait until ready, press Share or Save. Peter fails if the wrong lap is cut, the video is not H.264, or the fallback claims an OS share sheet appeared.
