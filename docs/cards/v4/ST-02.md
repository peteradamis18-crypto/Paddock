# ST-02 Shot-list engine + presets
**Phase / depends on / size / needs Peter:** Phase 5 / ST-01 / M / none
## Why
Create deterministic camera cues from real corner pct/time and camera IDs present in the session YAML. No guessed track geometry or car art.
## Read first
Read AGENTS.md, CLAUDE.md, docs/COPY-RULES.md, SPEC-v4.md §§1,3,5, docs/corners.md, docs/vault.md. Existing: Analysis.Load (dash/src/analysis.cs:300), Analysis.TAt (476), Analysis.Measure (539), Replay.Do (dash/src/replay.cs:334). These helpers are private. Corners members must be read from dash/src/corners.cs before use. Studio.cs and Studio.BuildShotList are new in prior cards.
## Build
1. Read exact corner and lap fields/units. Normalize pct to [0,1]; reject nonfinite, duplicate, reversed or out-of-range values.
2. Add shot model and BuildShotList(ibtFile, lap, preset). Each shot serializes cameraGroup, camera, startPct, endPct, startMs, endMs, slowMo. Derive cue times from this lap via the equivalent of Analysis.TAt; use milliseconds relative to session time, with conversion at one boundary.
3. Use only groups/cameras in that session YAML. CINEMATIC alternates validated TV/scenic and cockpit/chase; ONBOARD cockpit/chase; BROADCAST validated TV. Fallback only to a valid camera. Slow motion only on measured worst corner; if missing, none.
4. Reject unknown preset, invalid lap, absent camera list and nonmonotonic cues. Extend studio-test.ps1 with real-format fixtures, not drawn map assets. C# 5; retain all safety and copy rules.

## Gate
Guarded offline tests: at least 12 numeric assertions covering 3 presets x 3 real-format track fixtures; pct bounds/end>start; time-at-pct within 50 ms; only worst corner slow motion; invalid pct/preset and absent camera rejected. Every check emits ok/FAIL; deliberately corrupting a fixture must fail. User later fails if cue lands at wrong corner.
