## Build
1. Verify the exact APIs and fields above. `Sdk.Latest` is a `Frame`; retain that single reference for the entire snapshot. Available per-car arrays evidenced in `field.cs`: `CarIdxLapDistPct` (fraction 0..1), `CarIdxLap`, `CarIdxLapCompleted`, `CarIdxPosition`, `CarIdxClassPosition`, `CarIdxOnPitRoad`, `CarIdxTrackSurface`, `CarIdxLastLapTime`, `CarIdxBestLapTime`. Do not claim `CarIdxF2Time`/`CarIdxEstTime` exists until confirmed in the installed SDK frame.
2. Add `dash\src\tv.cs` (new) as a `static class Tv` in the existing source namespace/style; add it to `dash\build.ps1` `$src` (existing file). Add minimal initialization/start wiring in `dash\src\irdash.cs` (existing). Keep background sampler `BelowNormal`, no more than one SDK frame read per sample, 100 ms cadence, no SDK broadcast messages.
3. Build a stable class/car lookup from the current session YAML. Reuse `RaceField`'s YAML helpers only if accessible; otherwise parse the same `DriverInfo` data locally. Use `DriverCarIdx`, each driver's `CarIdx`, `UserName`, `CarNumberRaw` (fallback to `CarNumber` only if Raw absent), `CarClassID`, `CarClassColor`, `CarClassShortName`; exclude pace cars and spectators. Missing YAML or invalid array slots produce an empty/incomplete snapshot, never fabricated cars.
4. Snapshot JSON fields are new and must be documented in code/test: root `{tick, track, config, lengthM, playerIdx, cars, battles}`; each car `{idx, num, name, classId, className, classColor, pct, pos, classPos, pit, lap, last}`; battle `{a,b}`. `pct` is fraction 0..1; `last` seconds; `lengthM` meters; positions/laps integers; `pit` boolean; classColor six hex digits without `#`. Serialize invariant-culture JSON, escaping strings with `Json_.S` (existing helper in `irdash.cs`). For leader gap and same-class interval use the verified timing arrays if present in the actual frame; otherwise derive only from wrapped lap distance and track length (`distance = wrappedPct * lengthM`) and a documented speed estimate. If no reliable speed/time exists, emit null, not a false zero. Do not use `LastLapTime` as a current gap.
5. Battle means same class and absolute relative time <=0.8 s continuously for >=5.0 s. Count elapsed time from `SessionTime` (not tick count); reset on missing car/frame, class change, or threshold break. Use the real relative time field when available; otherwise do not assert a battle from pct alone without a valid speed-based time conversion. Handle wrap at start/finish.
6. Add GET `/tv/data` as a new route in `irdash.cs`; leave existing GET `/tv` toggle response unchanged. Return latest snapshot, 503 only if the TV data contract explicitly requires hiding during `Program.IsDriving`; SPEC 3d requires the live room view while racing, so `/tv/data` must remain readable during a race. Return an empty session state when disconnected. No new feed route: use existing guarded `/api/test/frame`.
7. Add `tests\tv-test.ps1` (new). Dot-source guard; call `Assert-RigFree` initially and before every `Section`. Start only the existing safe test harness as the precedent requires. Feed 3 cars with fixed frame arrays and YAML; check all values, JSON types, one-frame consistency, wraparound, missing arrays, and class filtering. Drive repeated `/api/test/frame` calls at 100 ms intervals for the battle duration; assert boundary at 4.9 s absent and 5.0 s present, and separation clears it. Assert reads remain available when pretend `IsOnTrack=1`; assert no outgoing SDK message exists.
8. Compile only with `powershell -ExecutionPolicy Bypass -File dash\build.ps1 -NoDeploy`. Do not deploy or open UI during a session.
