## Why
Today the RACES list is `Recorder.RacesJson` (`dash\src\recorder.cs` ~1933): a flat list with no thumbnails, no
state line, no trash, a two-press delete that frees space at once, and a retention that still deletes unsaved
sessions by count and budget. Peter: "delete when done so I don't nuke the hard drive", "deleting from HD needs to be
easy and clear" (2026-11-12). Evidence 04 §6 and PLAN §4.3: tick → bar → trash with UNDO, no "are you sure", a storage
line, "never deletes an unshared race by itself; never deletes a Kept race".

## What to build (`dash\src\library.cs`, already in `dash\build.ps1`'s `$src`; replace the stub)
**`SessionIndex`** — the one read model of recorded sessions: wraps the recorder's finished sessions (`Recorder`'s
`sessions` list, their sidecars `vault\sessions\<id>.json` or, once kept, `vault\saved\<id>.json` — `SavedDir`:
`Recorder.Save` moves a finished session there, and every race of 5 minutes or more is kept by itself, so today's 3
races are in `saved\` and the 8 practice/qualifying sessions in `sessions\`; schema 2) and their lap truth (`Recorder.RaceLaps`:
`LapStore.Best`, counted laps; W0-6). One method `SessionIndex.All()` → `List<RaceInfo>` newest first, and
`SessionIndex.Get(id)`. `RaceInfo` is a plain class: Id, Track, Config, Car, Type, IsRace (the rule used today:
`/race/i` and not `qual|prac`), StartMs, Sec, Laps, Counted, Best, BestLap, Bytes, Kept (`RecSess.Saved`), File,
Sidecar, InTrash, DeletedMs, Markers. Keep `Recorder.RacesJson` working (the old deck screen uses it until W1-5 lands)
but make it a thin call into the index so there is one list.

**Markers** (for the OPEN card's timeline, W1-4, and the chapters, W1-3): from the sidecar: `start` (lap 1's offset,
else 0), one `incident` per incidents row (label "Incident +2x" from `count`), `pit` per lap row with `pit:true`, `best`
(the counted best, "Best lap 1:33.832 (lap 9)"), `finish` (last lap row's offset + time). Add `"pit":true|false` to the
lap rows the recorder writes from now on (`SessJson`, `RecLap.Pit` exists) — one small change in `recorder.cs`, say so
in the report; old sidecars simply have no pit markers.

**`Library`** — the actions, each idempotent and logged in one line:
- `Trash(ids)`: moves `<id>.mp4` + `.json` (from `sessions\` or `saved\`; the batch remembers which, so UNDO puts
  them back where they were) to `vault\trash\` (same volume: a rename, instant), deletes the
  `Videos\Paddock` hard link (`Recorder.Export`'s `ExportDir`/`ExportName`), remembers the batch for UNDO, returns
  the batch id. Refuses while the session is being recorded or finishing (as `Recorder.Delete` does). A Kept race CAN
  be trashed by an explicit press (Peter chose it); nothing automatic ever trashes a Kept race.
- `Undo(batch)`: moves the files back and re-exports (hard link). Works for 8 s on the page, but the server keeps the
  batch for 60 s (a slow press must still work).
- `EmptyTrash()`: deletes trash items older than 14 days; `EmptyTrashNow()` all of them. Both as `Jobs.Run(whenFree)`.
- `FreeUpSpace()`: deletes (for good, not via trash) the oldest races whose share state is `shared`, oldest first,
  until 15 % of the volume is free; returns how many and how many GB. Never touches `none`/`sharing`/`failed` races or
  Kept ones. Uses the `ShareState` hook (below): with no hook it frees nothing and says so.
- Retention (replaces the count/budget rule for FINISHED sessions in `RetainSessions`): practice and qualifying
  (not IsRace, not Kept) go to the trash after 14 days; races are never removed by themselves; the trash empties after
  14 days. Below the recorder's hard floor (`MinFreeGbSession`) the trash empties early, then the oldest unkept
  practice/qualifying go, one at a time with a re-measure (the 2026-10-17 lesson in the code). All of it is a
  `Jobs.Routine("library tidy", …)` once a minute, so nothing happens while a session is on. Keep the blip rule
  (under 90 s, no lap). Say in the report what `RetainSessions` still does and what moved.
- Thumbnails: `vault\thumbs\race-<id>.jpg` (600 px wide) and `race-<id>-144.jpg` (144×144 centre crop for a deck key),
  one ffmpeg run per race (`-ss <start marker + 60 s, or 60 s> -frames:v 1 -vf scale=600:-1`), made by
  `Jobs.Run("race thumbnails", …, whenFree)` after a session and at start-up for the ones missing, newest first,
  `Jobs.ShouldYield` between files. In `irdash --test` the recorder's `RecMock` stands in for ffmpeg: make it write a
  1-pixel JPEG for `-frames:v 1` so tests have files.
- Storage: `UsedBytes` (the sessions folder), `FreeBytes`, `TrashBytes`, `MoreRaces` (free ÷ the average race size, 1.2 GB
  when there is none), `LowSpace` (free under 15 % of the volume).
- Two hooks the lead wires at merge time (W1-2 is built in parallel and cannot be referenced here):
  `public static Func<string, string> ShareState;` (race id → the `state` JSON object below; null hook → `{"kind":"none"}`)
  and `public static Func<string> YouTubeJson;` (null → `{"signedIn":false,"privacy":"private","template":1}`).

**HTTP** (in `irdash.cs`'s route table next to `/api/rec/*`, GET, read-only, no header needed):
- `GET /api/library` → exactly:
  ```
  {"storage":{"usedGb":412,"freeGb":280,"trashGb":14,"moreRaces":38,"lowSpace":false},
   "youtube":{"signedIn":false,"privacy":"private","template":1},
   "races":[{"id":"…","track":"Road Atlanta","config":"","car":"Toyota GR86","type":"Race","isRace":true,"startMs":1763050000000,
             "sec":1268,"laps":10,"counted":7,"best":93.832,"bestLap":9,"mb":1101,"kept":true,"thumb":true,
             "state":{"kind":"none"},
             "markers":[{"sec":0,"kind":"start","label":"Start"},{"sec":412.5,"kind":"incident","label":"Incident +2x"},
                        {"sec":780.1,"kind":"best","label":"Best lap 1:33.832 (lap 9)"},{"sec":1248.0,"kind":"finish","label":"Finish"}]}],
   "trash":[{"id":"…","track":"…","car":"…","type":"Practice","startMs":…,"mb":536,"deletedMs":…,"daysLeft":12}]}
  ```
  `state.kind` is one of `none | queued | sharing | shared | failed | signin | offline`; with `pct`, `privacy`
  (`private|public`), `url`, `error` when they apply (W1-2 fills them; here only the default).
- `GET /api/library/thumb?id=…&w=600|144` → the JPEG (`Cache-Control: max-age=86400`), 404 when not made yet.
- `/deck/summary`'s `races` part (irdash.cs ~1109 `StateBuilder.AddDeck("races", 10000, Recorder.RacesJson)`) now
  comes from `Library.DeckJson()`: the 40 newest with `id, track, car, type, isRace, startMs, sec, laps, best, mb, kept,
  thumb, state` and `storage` — no markers, no trash list. The old deck screen reads `races[].min` and `freeGb`: keep
  those two names in `DeckJson` too until W1-5 replaces the screen.
- `StateBuilder.BumpLists(false, false, true, false)` after every library change, so pages reload without polling.

**Commands** (`/api/do?c=…&a=…`, through `Vault.Do`'s switch or a `Library.Do` next to it; all GuardedDo in
`rigstate.cs` — they delete or move GB files, so never while a session is on; W0-2's header rule already applies):
`racetrash a=id|id|id` → `{"batch":"…","count":3,"mb":…}`; `raceundo a=<batch>`; `raceempty`; `racefree`
(FreeUpSpace); the existing `recsave` stays the KEEP toggle. `racedelete` (the old two-press delete) now trashes too
(same code path), so the old screen is safe until it goes. Answer text on `/api/do` is what the page shows in
plain words ("Deleted 3 races", "Nothing to undo", "Freed 7 GB: 6 shared races").

## Tests
- `tests\library-test.ps1` + `tests\library-main.cs` (the `tests\recorder-owner-test.ps1` pattern: compile the `$src`
  list from `dash\build.ps1` with the test main, reflection for private statics; a scratch vault under
  `tests\library-scratch\` with 1-KB pretend mp4 files and real schema-2 sidecars; `Jobs.SessionOn` pretend):
  1. index: 3 sessions → 3 RaceInfo newest first, IsRace right for Race / Lone Qualify / Practice, Best from the
     sidecar rows, markers in order (start, incident, pit, best, finish) with the labels above.
  2. trash → files in `vault\trash`, export link gone, list shows it under `trash` with `daysLeft` 14; undo → back,
     re-exported; undo twice → "Nothing to undo"; undo after 60 s → refused.
  3. retention: a 15-day-old practice goes to the trash, a 15-day-old race does not, a Kept practice does not, a 15-day
     trash item is deleted; `Jobs.SessionOn` true → nothing moves; the blip rule still holds.
  4. free up space: with a hook saying `shared` for the two oldest races, `racefree` deletes exactly those, oldest first,
     and stops at 15 %; with no hook it deletes nothing.
  5. storage maths: used, free, trash, moreRaces (fixture sizes), lowSpace.
  6. `/api/library` JSON parses and has every name in the contract; `DeckJson` has `min` and `freeGb` too.
  7. thumbnails: the job writes `race-<id>.jpg` and `-144.jpg` for every race (RecMock), newest first, and yields when
     `SessionOn` turns true mid-way.
