## What to build (all three)

### 1. Telemetry replay
- **In irdash (test hook only):** `GET /api/test/ibt?file=<path>&speed=20&from=<s>&to=<s>` starts a replay of an
  .ibt file through the existing pretend-session pump: the session YAML from the file via `FakeSession`, then every
  record (or every n-th at high speed) pushed with `FakeSet` so that the pump publishes it at `speed`× real time
  (`FakePumpMs` as today). Channels: every scalar the pages and the recorder read plus the `CarIdx*` arrays
  (`CarIdxLapDistPct`, `CarIdxPosition`, `CarIdxClassPosition`, `CarIdxLap`, `CarIdxOnPitRoad`, `CarIdxF2Time`,
  `CarIdxBestLapTime`, `CarIdxLastLapTime`, `CarIdxTrackSurface`, `CarIdxEstTime`, `CarIdxGear`, `CarIdxRPM`; use the
  `_n` slot keys the pump already understands). Gated exactly like `/api/test/frame` (409 while a real session is
  on, 404 without `test-hook.on`); `/api/test/end` stops it; `/api/test/ibt?status=1` reports position, speed and
  records sent. Put the code next to the pump in `irdash.cs` as one small class (`IbtReplay`), the smallest hunk you
  can: other builders edit that file too.
- **Wrapper** `tests\tools\replay.ps1 -File <ibt> -Speed 20 [-From 0 -To 600] [-Base http://localhost:8199]` that
  starts it, waits, and prints the status. The lead runs it against the live irdash when the rig is free.
- **The fixture file:** `tests\fixtures\race-12nov.ibt` = the first 3 minutes of
  `C:\Users\peter\OneDrive\Documents\iRacing\telemetry\toyotagr86_roadatlanta full 2026-11-12 09-28-07.ibt` (the race
  Peter won; laps 9-10 are the freeze, so also make `race-12nov-lap9.ibt` = the 60 s around lap 9's start/finish),
  cut by a tool `tests\tools\ibt-cut.ps1` that copies the header + session YAML + the chosen records and patches the
  record count. Add `tests/fixtures/*.ibt` to `.gitignore` (they are MB-sized); the test builds them when missing
  and skips with a clear line when the source file is not there.

### 2. Pretend irdash (`tests\tools\pretend-irdash.cs`, compiled with csc by `tests\tools\pretend-irdash.ps1`)
- An `HttpListener` on a port you pass (default 8299) that answers every GET route the add-on and the pages use
  from `tests\fixtures\irdash\<route>.json` (slashes → `_`): record them once with `pretend-irdash.ps1 -Record`
  from the live irdash (read-only GETs; allowed only when `irdeck-cli.exe state` says `sim=False`; the list of
  routes: `/showcase`, `/overlays`, `/guest`, `/mydrive`, `/replay`, `/api/rec/races`, `/workbench/state`,
  `/sound?peek=1`, `/ac`, `/home`, `/career`, `/keymsg`, `/nav`, `/version`, `/health`, `/debrief/state`, `/vault`,
  `/vault/item`, `/perf/live`, `/sessions`, `/doctor`; add what you find in `deck-intro/plugin.html` and
  `dash/www/v2/*.js`). Check the recordings in: they are small JSON.
- Fault modes set by `GET /__fault?mode=ok|500|slow|hung|down[&route=/x]`: `500` answers 500, `slow` waits 5 s,
  `hung` accepts and never answers, `down` closes the listener until `ok`. `GET /__stats` returns per-route counts
  and requests per second over the last 10 s (the request-rate ceilings in later cards read this); `/__reset`.
- `/stream` in telemetry mode: `pretend-irdash.ps1 -Ibt <file> -Speed 20` serves `/stream` from the .ibt in
  irdash's exact wire format at the page's rate (copy `Stream()`), so a page test needs no real server. `/api/do`
  answers `ok` and logs the command into `/__stats` (the deck tests check what was sent).

### 3. Pretend Google (`tests\tools\pretend-google.cs` + `.ps1`, default port 8399)
- `POST /token` → `{"access_token":"t-<n>","expires_in":3600}`; fault `invalid_grant`.
- `POST /upload/youtube/v3/videos?uploadType=resumable` → 200 with `Location: http://localhost:8399/upload/session/<id>`;
  records the snippet/status JSON.
- `PUT /upload/session/<id>` with `Content-Range: bytes a-b/total`: stores the bytes, answers `308` + `Range:
  bytes=0-<last>` for a non-final chunk, `200` + `{"id":"vid<id>","status":{"privacyStatus":"<as sent>"}}` on the last;
  a `Content-Range: bytes */total` query answers 308 + Range (or no Range when nothing received); a non-contiguous
  chunk answers 400 and marks the session `broken`.
- Faults: `drop` (close the socket after half a chunk, once), `500once`, `503once`, `401once`, `404session`,
  `uploadLimitExceeded`, `forbiddenPrivacySetting`, `slow`, `thumb403` (for `POST /upload/youtube/v3/thumbnails/set`).
- `GET /__stats`: per session the bytes received, the chunk list with offsets, whether any byte range arrived
  twice, the final JSON; `/__fault`, `/__reset` as above.

## Tests (`tests\tools-test.ps1`, offline)
- Pretend irdash: every recorded route answers 200 with valid JSON; `hung` gives no answer within 5 s; `down` refuses;
  `/__stats` counts; `/stream` in telemetry mode delivers the 12 Nov laps (the lap counter reaches 2 within the
  3-minute fixture at 20×).
- `ibt-cut`: the cut file opens with the same decoder and reports the right record count and the same YAML.
- Pretend Google: a 25 MB random file uploaded in 8 MiB chunks by a 40-line PowerShell client with `drop` after chunk
  2 resumes at the right offset, finishes with an id, and `/__stats` shows no byte twice and no gap.
- The irdash route compiles (`dash\build.ps1 -NoDeploy`) and refuses without the test hook (unit-test the gate the
  same way the existing test-hook tests do, offline).
