## Why
Seven different "is he busy" tests exist and several actions that click, launch or delete use the wrong one: MY
DRIVE's find keys and AI LEVEL start run iRacing UI automation while a session is connected in the garage; `ovl
apply` restarts irdashies in the pit box; a paired phone can shut the PC down mid-race; the Rig Doctor runs its
fixes mid-race; `SyncExports` deletes a race when its export was renamed; after any recorder test retention drops
to 3 sessions; one exception on a bare thread ends irdash with no log line; the log is wiped at 2 MB.

## What to build

1. **`RigState`** (new `dash/src/rigstate.cs`): one static class updated by the SDK thread, read by everyone.
   `SimRunning` (process exists; one constant for the process name, replacing the ~15 inline copies),
   `SessionOn` (SDK connected and the sim process exists), `Driving` (`IsOnTrack`), `StartPressed` (the
   `dash\start-mark.txt` rule, 10 min), `Busy` = `SessionOn || StartPressed`, `BusyWhy` (one sentence), and a
   `Since` time for each. Replace `IsDriving`, `CarMoving`, `RealBusy`, `Busy()` (official), `BusyWhy` by
   reflection (realworld) and the inline process lookups with it. Keep the old names as one-line forwarders only
   where more than five callers exist, and say so in the report. Serve it at `GET /rig/state` (JSON, read-only,
   allowed from anywhere) so `tests\guard.ps1`'s `Get-RigBusy` and the deck can share the one rule later.
2. **Session guards** (refuse with HTTP 409 and one plain sentence, logged once a minute at most): mydrive
   `mdfindcar` / `mdfindtrack` / `mdfindlayout` / `mdstart`, `AiLevel.Start`, `Doctor.Run` (show the cached result
   instead), `ovl apply` and any overlays restart, every vault and recorder route that changes files
   (`/api/rec/backfill`, `/api/rec/delete`, `/api/rec/save`, `recsave`, `racedelete`, `EditRoute star=1`), the
   `/analysis/pro/save` and `/delete` routes, `SpotterGuard` launching or killing CrewChief: all require
   `!RigState.SessionOn`. The Stream Deck restart in `Watch` stays allowed while driving but logs "restarted during
   a session".
3. **Phone allow-list** (`phone.cs`): while `SessionOn` a paired phone may only run the audio, pit, chat and
   spotter commands (list them from the phone page's own buttons); everything else answers "not while a session
   is on". Non-local callers get a **path allow-list** (the phone's routes only), not the `Hidden` deny-list. The
   token is accepted from the header or cookie only (never `?t=`), the cookie is HttpOnly, 60 s lockout after 8
   bad codes, `/phone/revoke?all=1` only from localhost. Listen on the default-route adapter only.
4. **State-changing routes need a header**: every `/api/do` and every changing route checks `X-Paddock: 1` (or a
   same-origin `Origin`); the top-screen pages, the add-on (`deck-intro/plugin.html` — one line in its fetch
   helper; W0-1 just added a timeout wrapper there, use it) and irdeck's HTTP calls send it. A blind
   `fetch('http://localhost:8199/api/do?c=...')` from any web page is refused.
5. **Crash handler**: `AppDomain.UnhandledException` + `Application.ThreadException` log the exception and keep
   the tray alive; every bare `new Thread` in `ac.cs`, `recaudio.cs` and the others gets a try/catch that logs.
   `double.Parse` in ac.cs becomes `TryParse`. The port-bind failure shows a tray balloon, not a `MessageBox`.
6. **Log rollover**: `Log.W` writes through one background queue; at 2 MB the file rolls to `irdash.1.log` (keep 3).
7. **`TestOff` restores the real defaults** (`keepSessions` 8, reload the clip list). **`SyncExports` never deletes**
   on a missing export: it marks the race "export missing" in the JSON and the RACES list shows that in words.
8. **`Vault.Serving` no longer gates the recorder's routes** (`/api/rec/*` and the deck's RACES list answer whether
   the Vault is on or off).
