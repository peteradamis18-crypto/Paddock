# W0-11 — Recorder: a segment belongs to one session

Follow-up to W0-3, found in Peter's real evening 2026-11-13 (Road Atlanta, Toyota GR86, one sim run: Practice 16:16,
Practice 16:17, Lone Qualify 16:19, Race 16:27). Builder: Opus. Rules: `docs/rework/cards/README.md`.

## What went wrong (irdash.log 16:48)
W0-3 made the session file a whenFree job: it waits until the sim closes. `BeginSession` in `dash\src\recorder.cs`
(the block `if (run != null) { run.Sess = s; ... s.Segs.Add(g); }`) therefore runs while the PREVIOUS session's
segments are still in `segs`. `run` is never cleared when ffmpeg stops, so the new session re-points the old run to
itself and adopts every one of its segments. Before W0-3 the previous file was written within seconds of its end, so
this adoption never met another session's segments.

Seen: Qualify's file (409.7 s) swallowed Practice 2's 74 s; Practice 2 "had no closed segments - nothing to write"
(its video is gone); the Race file logged "is missing segment rec-20261113-2119xx…" 35 times (Qualify's segments,
already joined and deleted by Qualify's job) and was marked "partial - 1 gap(s)" although its own 1268 s are complete.

## Fix
A run belongs to the first session it recorded for.
- In `BeginSession`, adopt a run only when `run.Sess == null` (ffmpeg started before the session was known). Never
  re-point a run that already has a session. Never adopt a segment that another session (`openSess`, `finishing`)
  already holds (`HasSessionOwner` exists; mind that it also looks at `Owner.Sess`, so check before re-pointing).
- Pull the decision into one small static method (for example `AdoptRun(RecSess s)`) so a test can call it by
  reflection. The private sealed classes `RecRun`, `RecSeg`, `RecSess` are fine to make through reflection.
- Leave `FinishSession`, the gap marking and the tidy as they are.
