## Why
The same race shows three different best laps (My Races 1:33.639 from an uncounted incident lap, Vault and
Sessions 1:33.919 because the counted rule rejected 7 of 10 clean laps, the real counted best 1:33.832 on lap 9),
a 10-lap race says 11 laps (lap 0 counted), eight "best lap" rules exist, `Gather` sees only the newest 40 files,
and HOME's "PB here" ignores the car. Rule 3: one truth per number.

## What to build

1. **`IbtFile`** (new `dash/src/ibtfile.cs`): open, header, session YAML, variable lookup, read one channel or a
   record range, `IsFinished` (the sim closed it), `SessionUniqueID`, start time from the header (then the file
   name; never the file's creation time). Built from `TrackMaps.OpenIbt` and the best of the 14 readers; the
   other decoders in `irdash.cs`, `analysis.cs`, `data.cs`, `corners.cs`, `career.cs`, `recorder.cs`, `vault.cs`,
   `gpsmap.cs`, `refs.cs`, `perf.cs`, `bench.cs`, `partial.cs`, `rawdata.cs` call it (replace each one you touch;
   leave a one-line note where a decoder stays because it reads something `IbtFile` does not).
2. **`LapStore`** (new `dash/src/lapstore.cs`): one lap record `{n, time, counted, pit, off, incident, start,
   startRecord, endRecord}` and one `Best(laps)` = the quickest counted lap. Live laps come from the SDK thread
   (the recorder's lap detector moves here); old laps from `IbtFile`. Per-session results are cached in
   `dash\data\laps\<file>.json` with ONE rules version (`LapRules.Version`); every other version number
   (`CrVersion`, `Rec.Rules`, `RefData.Rules`, `VSession.Rules`) is replaced by it, and a cache with an older
   version is rebuilt (as a `Jobs` job when W0-3 has merged, else on the existing worker).
3. **One counted rule** (`LapRules.Judge`, rewritten, with the fix list from 09 §1a): lap 0 (the formation /
   out lap) is never a lap; `counted` is true when iRacing's own `LapBestLapTime` or `LapLastLapTime` confirms
   the time: live, the recorder sees `LapLastLapTime` change at the line and `LapBestLapTime` follow (compare with
   the last lap seen, not the previous frame, so a same-frame update is not missed); in a file, look in a window
   of about 4 s after the line (not 1.5-2.5 s) and take the matching time; an incident in the lap
   (`PlayerCarMyIncidentCount` rising) marks `incident` and does not count the lap; one off-track record is not
   fatal (use iRacing's own verdict; keep `off` as information); a pit lap (`OnPitRoad` at any record) is `pit`
   and not counted; a lap with no official time within the window is `counted:false` with reason `no-time`.
   Keep the one constant set in `LapRules` (window sizes, minimum lap 15 s) with a comment that says why.
4. **Everyone uses `Best()`**: My Races (`RacesJson`: counted laps only, lap 0 out, `laps` = counted + uncounted
   real laps, best = `Best()`), the Vault card and `sessions.tsv`, Sessions page, Coach / Session Review, Career
   (no "quickest announced lap" fallback; `-1` means "no counted lap", shown as "no clean lap"), HOME's "PB here"
   (same car and track, not all cars: N5), the deck RACES list (through `/api/rec/races`), the PB reference
   (`refs.cs`: adopt only counted laps; `pb:true` in the recorder uses the same flag), `Gather` (no 40-file cap:
   use the lap cache; N6), `bench.cs` `FieldLaps` where it judges laps.
5. **The 12 Nov test** `tests\lap-truth-test.ps1`: with `toyotagr86_roadatlanta full 2026-11-12 09-28-07.ibt`
   (`C:\Users\peter\OneDrive\Documents\iRacing\telemetry`; skip with a clear line if missing), `LapStore` reports
   10 laps, 9 counted, lap 6 `incident` and not counted, lap 0 absent, `Best()` = 1:33.832 on lap 9; then every
   JSON that shows a best for that session (`/api/rec/races` entry, Vault card, Sessions row, Career, Coach) says
   1:33.832 and 9 counted. Use the W0-8 fixture cut (`race-12nov.ibt`) for the fast part and the full file for
   the once-per-run check. Also a synthetic-lap test of `Judge` (pure C#): the cases in item 3, one each.
