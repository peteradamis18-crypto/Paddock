## The screen (1920 x 1080 under the shell header, the page area is 992 px; shell tokens only, no new colour, no new font size)
1. **Ready line** (top, big): "Rig ready" in gold when Stream Deck, Spotter and Overlays are ok (iRacing closed is not a fault);
   else ONE sentence for the first fault in this order: Stream Deck → Spotter → Overlays, plain words ("Stream Deck is not
   running") with ONE button: FIX, which calls `GET /api/doctor/run?quiet=1` (the Doctor's own fix, `doctor.cs RegFixes`);
   greyed with "Not while driving" when `rig.driving` (the Doctor refuses in a session). While the Doctor runs, the line says
   "Checking the rig…" (poll nothing: the `doctor` part carries `running`).
2. **Four rows**, each a name, a dot and a word, from the `health` part (`/health` apps): iRacing = `ui` + `sim` in one row
   ("in a session" when sim is live, "open" when ui ok, "closed" grey when both off: never red); Stream Deck = `deck`
   (running / not running red); Spotter = `cc` (running / off red; "not installed" grey when the app is missing from the list);
   Overlays = `overlays` (running / off red; "not installed" grey when missing).
3. **LAST RACE**: from `/perf` `last` (keys in facts §1): average fps · worst second "23.7 fps · lap 9, start/finish" (from
   `freeze.lap` + the slowest of `places` when there is no freeze: its from/to) · the verdict `text` once. When `/perf` `summary`
   contains "still being processed", say that in the three numbers' place. The 12 Nov file must read "Lap 9 … 23.7 fps".
4. **QUIET PC**: the `quiet` state part (W5-2's contract): `{"setup":bool,"on":bool,"since":<ms>,"say":"<one line>",
   "items":[{"id":"update|search|onedrive|simprio","name":"Windows Update","state":"paused|running|off|on|unknown"}]}`.
   Render `say` and one dot per item. Part absent or `setup:false` → "Quiet PC · not set up" in grey (no button: the setup is
   a one-click file the lead hands Peter, rule 5).
5. **AC**: when `GET /ac` says `connected:true`, the deck's AC controls restyled for the screen: POWER, temperature − / +
   with the target and the room, MODE, FAN, the three presets (MAX / COMFORT / QUIET), AUTO; every press is the same
   `/api/do?c=ac*` the deck sends (facts §5), idempotent, with the keymsg-style answer on the page. Not connected → one grey
   line "AC not connected". Never poll `/ac` faster than the `ac` state part (2 s): read that part.
6. **Switches** (big, two states, the current one filled): START-UP SOUND on/off and MIC "<name>" with NEXT. Contract (yours):
   `dash/src/rigpage.cs` (new): ini keys `startup_sound=on|off` (default on) and `mic=<endpoint friendly name>` (default empty =
   Windows' default); `GET /api/settings` → `{"startupSound":true,"mic":"<name or empty>","mics":[{"name":"...","default":bool}]}`;
   `/api/do?c=startupsound&a=on|off`, `/api/do?c=mic&a=next|<name>`; state part `settings` (1000 ms) with the same JSON.
   The mic list is read from the registry, no process and no COM: `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\MMDevices\Audio\Capture\{id}`
   with `DeviceState` = 1 (active) and the friendly name in `Properties` value `{a45c254e-df1c-4efd-8020-67d146a850e0},2`
   (fall back to `…},14` the interface name). `startup.js` asks `GET /api/settings` (300 ms timeout; on no answer it keeps
   today's rule) and stays silent when `startupSound` is false; quiet hours still apply. `dash/www/v2/player.js:35` lists devices
   with `enumerateDevices()` after `getUserMedia` and re-opens the stream with the `deviceId` whose label contains the chosen
   name (else Windows' default; the recorded `mic` field, `commentary.cs:73`, keeps saying which one was used).
7. **Nightly line** (small, under the rows): the `nightly` part (W5-4's contract `{"at":"<iso>","text":"Rig check 03:00: all good","ok":bool}`);
   absent → nothing shown.
8. Foot: MORE (the old Performance page in the frame) · CLOSE is the shell's. Offline (the shell's `online:false`): everything
   greys, nothing is asked (as REVIEW does). `data.on(...)` for every part; no setInterval (the design lint checks).
