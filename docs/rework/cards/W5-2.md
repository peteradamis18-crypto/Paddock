## How it works (lead's design; say in your report if a fact below turns out wrong, do not silently change the design)
- **Setup, Peter's one click:** `tools\quiet-pc-setup.cmd` (+ `tools\quiet-pc-setup-UNDO.cmd`) runs `tools\quiet-pc.ps1 -Setup`
  elevated (the `Start-Process -Verb RunAs` pattern of `tools\rig-cleanup.ps1`). Setup registers two scheduled tasks,
  "Paddock Quiet PC on" and "Paddock Quiet PC off", for user PETER\peter with highest privileges, no trigger, actions
  `powershell -NoProfile -ExecutionPolicy Bypass -File <repo>\tools\quiet-pc.ps1 -On` / `-Off`, and writes `data\quiet-pc\setup.json`
  (when, which tasks). UNDO runs `-Off`, deletes both tasks and the json. A non-elevated process may start its own user's task
  (`schtasks /Run /TN "Paddock Quiet PC on"`): that is how irdash, which is not elevated, gets the services paused without a
  prompt. Prove this on a stand-in task in your test (a task of your own that writes a file), never on the real ones.
- **On** (`quiet-pc.ps1 -On`): stop the services `wuauserv`, `UsoSvc`, `WSearch` IF running, and `OneDrive.exe /shutdown` if a
  OneDrive process is running; write what WAS running to `data\quiet-pc\state.json` so Off restores exactly that and nothing
  more. **Off** (`-Off`): start the services that were running, `OneDrive.exe /background` if it was. `-Status` prints the
  JSON below from the service states (`Get-Service`, no administrator needed to read) and the OneDrive process. `-Preview`
  changes nothing and prints the plan. Every run appends one line to `tools\quiet-pc.log`. Nothing else is touched: no
  registry, no policy, no "pause updates" setting (to confirm in a later card whether Windows restarts `wuauserv` mid-session;
  log it when the Status read sees it running again while on).
- **irdash** (`dash/src/quietpc.cs`, new): on session START (add `StateBuilder.SessionStarted`, the mirror of `SessionEnded`
  at `statebuilder.cs:213/231`, fired when `SessionOn` rises) → if `setup.json` exists, run the "on" task (`schtasks /Run`,
  BelowNormal, 10 s timeout, never waits on the UI thread); on session END → the "off" task; at irdash start, if `state.json`
  says on and no session is on → the "off" task (a crash must not leave the PC quiet). The hooks are the ONLY callers; no
  `/api/do` command turns quiet-PC on or off (nothing to press, nothing to forget).
- **Sim priority kept:** `SimPriority.Tick` (`data.cs:885`) applies High once per pid today. Re-apply every 30 s while
  `RigState.SessionOn` when the sim's class is below High (the Doctor already notices, `data.cs:921`); log once per session
  when it had to. Needs no administrator unless the sim is elevated: then log "could not raise (the sim runs elevated)" once.
- **State part `quiet`** (1000 ms; this is W5-1's contract, keep it exactly): `{"setup":bool,"on":bool,"since":<ms or 0>,
  "say":"<one line>","items":[{"id":"update","name":"Windows Update","state":"paused|running|unknown"},{"id":"search","name":"Search
  indexing",...},{"id":"onedrive","name":"OneDrive","state":"paused|running"},{"id":"simprio","name":"Sim priority","state":"on|off|unknown"}]}`.
  `say`: "Quiet PC · not set up" / "Quiet PC on since 20:14 · Windows Update, search and OneDrive paused" / "Quiet PC off ·
  everything handed back". Read the real states with `ServiceController` and the process list every 10 s at most, cached.
- Logs: `dash/irdash.log` one line per on/off; `tools\quiet-pc.log` from the script.
