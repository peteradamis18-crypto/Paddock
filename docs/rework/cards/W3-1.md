## What to build
- **`app/index.html`** (the top screen's one page, served as the dashboard: change irdash's default `Page` to `app/`
  and keep `v2/` served): `<header>` PADDOCK · the date (local, "Fri 14 Nov") · the four doors HOME · RACES · REVIEW ·
  RIG as 32 px words (the current one gold; a door is a `<button>`); `<main id="page">`; one `#banner` (48 px) used for
  exactly one thing at a time: offline ("Paddock is not running. Press HOME on the deck."), kids mode, tow wait, a
  key message (4 s), in that priority; `#raceHost` (the W2-2 race page, full-screen while driving); the flag glow; the
  start-up layer `#startup` (W3-2 mounts into it; the shell only shows/hides it); nothing else.
- **The router** (`shell.js`, an ES module): `#/home` (default), `#/races`, `#/review`, `#/rig`; exactly one page
  mounted at a time; `go(name, opts)` unmounts the current page first; Esc and CLOSE (every non-HOME page gets a 64 px
  CLOSE top-right from the shell, not from the page) go to HOME; Esc works inside iframes too (the hosts forward
  `keydown` Escape by `postMessage({paddock:'esc'})`, the shell listens); the deck's `nav` part (`to` + `seq` rising)
  calls `go`; `/api/nav?to=home` is answered when a page closes (as pagehost does today) so irdash's `nav` stays true;
  the driving guard: when `data.rig.driving` on a fresh frame (W2-2's rule, moved here: the `RaceSwitch` logic leaves
  `ui.js` and lives in the router), every page unmounts and `#raceHost` shows; 5 s after driving ends, HOME mounts and
  the after-drive card (W3-3) is HOME's business; the banner priority above; a page may call `ctx.banner(text|null)`
  for its own one-liner.
- **Page module contract** (`app/pages/<name>.js`, ES module):
  ```
  export default { name: 'home', title: 'HOME',
    mount(el, ctx),            // el = #page (empty), ctx = { data, Fmt, go, close, banner, kidsOn(), driving() }
    unmount(),                 // remove listeners/timers; the shell empties el
    onState(state, changed) }  // optional: the shell forwards data.on('state')
  ```
  Pages never poll: `ctx.data.onList`, `ctx.data.on`, `ctx.data.json(url, ttl)` only.
- **`app/pages/races.js`**: the W1-4 page (`v2/races.html` + `races.js`) converted to this contract and `v2/races.*`
  deleted (its test `tests\races-page-test.ps1` runs it through the shell with `?page=races` instead; keep the 154
  checks, adapt the harness); the RACES door and the deck's RACES key land here.
- **`app/pages/review.js`** and **`rig.js`**: thin hosts until waves 4 and 5: an iframe of `v2/sessions.html?embed=1`
  (REVIEW; it opens the latest drive) and of `v2/perf.html?embed=1` (RIG); CLOSE and Esc as above; nothing else.
- **HOME before W3-3 lands**: a placeholder `app/pages/home.js` that shows the clock words "HOME is being rebuilt" in
  the type scale, so the shell runs alone; W3-3 replaces the file (merge order: this card first).
- **Old files**: `v2/index.html`, `ui.js` (its `RaceSwitch`, `KidsMode`, `TowWait`, overlay), `home.js`, `home.css`,
  `pagehost.js`, `nav.js`, `intro.js`/`intro.css` retire when W3-2 and W3-3 land (the lead deletes them at the last
  merge; you list in your report every piece of `ui.js`/`core.js` the shell still needs, e.g. the flag table, the
  tow/kids text, `UI.live()`, and move those into `app/lib/` as you go).
- Request budget (W0-5): HOME idle ≤ 2/s, driving ≤ 1/s besides the stream, nothing on a timer in the shell except the
  clock second hand (W3-2) and the 5 s driving-end wait.
