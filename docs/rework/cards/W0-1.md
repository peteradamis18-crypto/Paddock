# W0-1 Deck safety (builder: Opus; Codex review before merge)

Read first: `docs/rework/cards/README.md`, `docs/rework/PLAN.md` §2 and §4.6 ("Safety and reliability"),
`docs/rework/evidence/11-audit-deck.md` (all of it: top findings 1-9, §1 table, §2, §3 A1-A6, §4).

## Why
A stray press on the Stream Deck can turn Peter's PC off today: the deck saves the LEAVE page as current, SHUT DOWN
PC and SLEEP PC are one press there, and after a wake or restart the deck can come back on that page. The repeat
guard that CLAUDE.md promises (0.7 s) does not exist (it is 0.12 s), `key` commands have no guard at all, the
add-on freezes on a hung irdash, and `irdeck state` (what every safety rule reads) is the least careful reader.

## What to build (all of it; each item has a test)

1. **Confirm screen for SHUT DOWN PC and SLEEP PC.** The two LEAVE keys (`build-deck.ps1` lines 201-202) stop being
   key exes. They become one add-on action ("Confirm") that opens a screen: a big gold key in the middle row that
   says `YES, SHUT DOWN` (or `YES, SLEEP`) with a 5-4-3-2-1 count painted on it, and the red `EXIT` at 7,3. Only
   the YES press runs the command (through `/api/do`, as the other screens do); after 5 s the screen closes itself
   and nothing happens. A second press of YES within the 0.7 s window is ignored. Keep the two exe commands
   (`shutdown`, `sleep`) in irdeck as they are; only the way they are reached changes. If the `/api/do` whitelist in
   `dash/src/irdash.cs` needs those two names, add them (smallest possible hunk; another builder is editing
   that file).
2. **MAIN on every Stream Deck start and wake.** When irdash's deck watchdog (`dash/src/irdash.cs` around lines
   1569-1694, `deckwatch.cs`) kills and restarts `StreamDeck.exe`, set the "iRacing GT3" profile's current page to
   MAIN in the profile manifest first (the app is stopped at that moment, so writing the manifest is safe; see how
   `build-deck.ps1` finds the profile and page ids). `build-deck.ps1` writes MAIN as the current page too. For the
   SHUT DOWN / SLEEP commands in irdeck: stop StreamDeck.exe, set the page to MAIN, (for sleep) start it again,
   then power off / sleep, so the deck comes back on MAIN after a boot or a wake. Put the manifest helper in a file
   compiled into both exes (`src/deckstate.cs` is already shared; add `src/deckprofile.cs` and list it in both
   build scripts). The helper never writes while StreamDeck.exe is running.
3. **Repeat guard: a real 0.7 s floor** for every key, mutex kept, except `vol-up`, `vol-down`, the spotter level
   keys and `seat-up` / `seat-down` by name. The `key` and `media` verbs lose their exemption. `irdeck.exe <args>`
   started by irdash or the add-on goes through one guard in irdash's `/api/do` keyed by command + argument (11 §1
   row 1.3). Fix CLAUDE.md rule 6 and `docs/ARCHITECTURE.md` so they say what the code does.
4. **Add-on hardening** (`deck-intro/plugin.html`): every `fetch` gets a 2 s `AbortController` timeout; a hung
   irdash shows `DASHBOARD NOT ANSWERING` within 3 s with EXIT at 7,3; opener keys go grey after 3 failed ticks and
   come back on the next good one; MY DRIVE never switches the deck by itself (A1: remove the auto-open; irdash may
   still say `NO CHOICE`, the key shows it). Do not restyle anything else; the screens are rebuilt in wave 3.
5. **Start mark:** `MarkStart` at the top of `airace start` and the official join (11 top finding 4).
6. **`irdeck state`:** one line that keeps every field it prints today (guard.ps1, `dash\build.ps1`,
   `deck-intro\install.ps1`, `tests\deck-speed-test.ps1` parse it; check them) and adds `fresh=` (tick moved within
   0.9 s), `replay=`, `event=` (Test / AI / Race / Practice / Qualify / none), and prints `telemetry=on` only when
   the sim process exists. `install.ps1` refuses on the shared busy rule (`Get-RigBusy` in `tests\guard.ps1`), not
   only on `telemetry=on`.
7. **`build-irdeck.ps1`** copies the new exe to every name in `keys\keys.map` (not only copies whose hash matches
   the old exe), retries a busy copy three times a second apart, and exits non-zero naming any copy left old.
8. **Messages that name keys that no longer exist** (11 top finding 8): "press RIG ON" becomes "press HOME", "use TOW TO
   PITS" becomes "use RESET CAR", "use QUIT x2 first" becomes "press QUIT TO MENU first". Fix the top-screen table in
   `dash/www/v2` that maps "press RIG ON" too if it exists (grep).
9. **Dead deck paths out** (11 top finding 9): the `confirm` / x2 arming path and `ConfirmArmedFresh`, the add-on's
   ARMED 3-2-1 state keys (`smart`, `quit`, `restart`, `skip` state keys, `paintStateKey`, `pollDeckState`), irdash's
   `/deck/state` route, `DeckStateResolver` if nothing but `smart --fake` uses it (then `--fake` goes too), and
   `_csc-official.ps1`. Delete `tests\confirm-test.ps1` and `tests\deckstate-test.ps1` and remove them from
   `tests\run-all.ps1`. Keep `RigDoctor` (wave 3 decides).

## Tests (offline, every one must pass; the lead runs the live ones)
- `tests\deckguard-test.ps1` (pure C#, deckrules pattern): two starts of the same key 0.3 s apart give one run;
  0.8 s apart give two; `vol-up` 0.3 s apart gives two; the `key` verb 0.3 s apart gives one; the `/api/do` guard
  works by command+argument.
- `tests\deckstate-line-test.ps1`: the `state` line parser used by guard.ps1/build.ps1/install.ps1 reads the new
  line; `telemetry=on` is never printed without the sim process (unit-test the decision function).
- `tests\deck-confirm-test.ps1` (headless Chrome + `deck-mock.js`, see `tests\deck-*` for the pattern): open the
  Confirm screen, YES sends exactly one `/api/do?c=shutdown`; a doubled YES sends one; EXIT sends none; after
  6 s the screen is closed and nothing was sent.
- `tests\deck-hung-test.ps1`: a PowerShell `HttpListener` on a spare port that accepts and never answers; the
  add-on shows DASHBOARD NOT ANSWERING within 3 s; an opener key is grey after 3 ticks and normal after one good
  answer. (W0-8 is building a fuller pretend irdash; a 20-line listener inside this test is fine for now.)
- `tests\deck-layout-test.ps1`: no key that ends the PC is a plain key exe on any page (reads the page tables in
  `build-deck.ps1`); the Confirm action exists in the manifest; every page's LEAVE/BACK target still resolves.
- `tests\build-irdeck-test.ps1`: with a temp `keys.map` of 3 names and one locked file, the copy loop reports the
  locked one and exits non-zero; with none locked all 3 are new.
- `tests\deckprofile-test.ps1`: the manifest helper sets `Pages.Current` to MAIN on a copy of the real profile tree
  under `%TEMP%`, refuses when a `StreamDeck.exe` process exists (mock the check), leaves other fields byte-identical.
- The existing `tests\keys-test.ps1`, `kids-test.ps1`, `deckwatch-test.ps1`, `deck-speed-test.ps1` (offline parts)
  still pass.
