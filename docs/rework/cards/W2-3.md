## What it does
Measures, from Peter's own stops, how much time a pit stop costs at each track, and remembers it. One number per
track: the median of his measured stops (seconds), with how many stops it rests on and when the last one was. Shown
only once measured (PLAN: "learned from his own stops and shown only once measured").

## How to measure (pure C#, fed one sample per frame at ≤ 15 Hz: SessionTime, OnPitRoad, Lap, LapLastLapTime,
LapDistPct, SessionFlags, IsOnTrack, PlayerTrackSurface, the track name from the session)
- A stop = `OnPitRoad` false → true → false on the same car within one session, with `PitstopActive` seen true (or the
  car stationary in the lane: LapDistPct unchanged for ≥ 2 s while OnPitRoad) so a drive-through without service
  counts separately as `driveThrough`.
- Time lost = (in-lap time + out-lap time) − 2 × the reference lap, where the reference lap is the median of the
  clean laps of that session before the stop (W2-1's "clean" rule: green, no pit, on track); the laps are the ones
  `Lap` crosses; a caution during the in/out laps or fewer than 2 clean reference laps → the stop is measured as
  "unknown" and not stored. Both halves are kept (`inLoss`, `outLoss`) so a future pit board can say "you lose 12 s
  entering, 18 s leaving".
- Store: `data\pitloss.tsv` (track, config, stops, median, mean, last, lastWhen, samples kept as a `;` list of up to
  20), written temp + move (`Jobs.Save`-style: a tiny write, allowed in a session), one line per track+config.
- `PitLoss.For(track[, config])` → the median when `stops ≥ 1`, else null. `PitLoss.Json()` for a later RIG/REVIEW page
  (`{"tracks":[{"track":…,"config":…,"stops":3,"median":31.4,"last":30.9,"lastWhen":…}]}`).
- Nothing runs on a request thread; no timer; the feed is the frame tick. Log one line per measured stop
  ("pitloss: Road Atlanta: 31.4 s (3 stops, median 31.4)").

## Tests — `tests\pitloss-test.ps1` (+ `pitloss-main.cs`, the `tests\cuts-test.ps1` pattern: compile `pitloss.cs` alone
with a main; no irdash, no rig)
1. a synthetic session: 4 clean laps at 95 s, an in-lap of 110 s, a stop with PitstopActive, an out-lap of 112 s, two
   more clean laps → one stop measured: loss = 110 + 112 − 2 × 95 = 32.0, inLoss 15, outLoss 17; the file has one line
   with stops 1, median 32.0; `For("Road Atlanta")` = 32.0; `For("Spa")` = null.
2. a second stop at the same track → stops 2, median of the two; a drive-through (no PitstopActive, never stationary)
   is counted as driveThrough and not in the median.
3. a caution during the out-lap → not stored; fewer than 2 clean laps before the stop → not stored.
4. a real file: find in `C:\Users\peter\OneDrive\Documents\iRacing\telemetry\` (read-only, one file, BelowNormal; only
   when `C:\Users\peter\iRacingDeck\irdeck-cli.exe state` shows sim=False) an .ibt with a pit stop (OnPitRoad goes
   true then false mid-session; `tests\tools\ibt-cut.ps1` can cut 3 minutes around it into `tests\fixtures\`), feed it
   through the module and print the measured loss; if no file has a stop, say so and skip.
5. the TSV survives a reload with the same numbers; a corrupt line is skipped with one log line.
