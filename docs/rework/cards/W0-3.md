## Why
Peter's worst freeze (12 Nov, lap 9, 112 → 24 fps for about 10 s) happened while Paddock was cutting a 90 MB clip
at normal disk priority, housekeeping could delete GB files every 5 s, the previous session's 1.1 GB encode could
run during the next session, the TV worker re-parsed YAML every 100 ms for a view that is off, the guard timer
ran process scans and WMI on the UI thread, and the overlays were re-raised every 5 s. None of it was measured.
Rule 2: nothing heavy while he drives.

## What to build

1. **`Jobs`** (new `dash/src/jobs.cs`): one background queue. `Jobs.Run(name, work, whenFree)`: `whenFree` jobs
   wait until `!RigState.SessionOn` for a 20 s grace period, then run one at a time on a BelowNormal thread with
   **background disk priority** (`SetThreadInformation` / `THREAD_MODE_BACKGROUND_BEGIN`, or the process-level
   `PROCESS_MODE_BACKGROUND_BEGIN` on a dedicated worker process: pick one, say which); one log line per job
   (name, waited, took). A job started while free that sees `SessionOn` begin finishes its current step and
   re-queues the rest where it can (document which jobs do). `Jobs.Status()` JSON for RIG and tests.
2. **Move onto `Jobs`, waiting for free:** recorder PB/incident cuts (cut from the whole-session file after the
   session; keep the lap times and marks during the session, nothing else), `Housekeeping` (retention deletes,
   `PruneSegs`, `PruneAudio`, `SyncExports`), `FinishSession` (the concat and AAC encode), the map builder (and
   look the sim up once per build, not per file), the reference build in `refs.OnCombo` and the `Adopt` write,
   `FieldLaps` appends (collect in memory during the session, write after), `GainPoke` and the career scan, perf
   reports, `Vault.SaveAll` (append one line now, save the rest after), official `BuildOwned` (never from `/home`;
   a job at start-up and every 6 h when free).
3. **Off the UI thread:** the 2 s guard timer's checks (`PlaceSim`, `KeepDash`, `Watch.Tick`, `Doctor.Tick`,
   `SimPriority.Tick`, `Guest.Tick`) run on one background thread and post only window moves to the UI thread;
   the delta bar keeps the UI thread to itself. `DeckPresent()` (WMI) cached 30 s, never on the UI thread.
4. **Stop the churn:** `RaiseOverlays` raises once when driving starts and then only when a check sees an overlay
   below the sim (no 5 s TOPMOST loop); `OverTaskbar` flips once. The doctor's 20 s `ClearStrayDialogs` /
   `TunerBox.HideNow` run once at session start, not during. `Overlays` reads `state.ini` through a file watcher
   (no 500 ms timer) and `/overlays` does no process scan per poll (cache 5 s). `Vault.StatusJson` caches sizes
   60 s and never walks the tree, the process list or the registry under the lock while `SessionOn`. `/mydrive`
   caches by file stamps and answers from cache while driving. `IbtLaps.Get`, `EnsureCopy`, `AttachClip`,
   `LinkClips` do their file work outside the lock.
5. **AC while driving (H5):** measure first: log the wall time and CPU time of each python call for a day of use
   (one line per call); while `SessionOn` call it every 10 min instead of 2, and never hold the lock across the
   call. **`PerfPrio` (H6):** behind a config switch `perf_prio=0` by default (Peter decides; the plan recommends
   off until the black box says it helps); when on, set once at session start, not every 5 s.
6. **Headless test mode for the load test:** `irdash.exe --test <folder> --port <n>`: no kiosk window, no
   watchdog, no delta bar, no recorder capture (mock recorder that writes 1 KB "segments"), no CrewChief/Stream
   Deck/overlay launching, data under `<folder>`, test hook on. Everything else (SDK reader with the pretend pump,
   HTTP, jobs, vault, maps) real. This is how the load test runs the real server without touching the rig.
7. **The load test** `tests\server-load-test.ps1` (layer 3; offline, uses the W0-8 tools): start irdash in test
   mode on port 8499 in `%TEMP%`, replay the 3-minute 12 Nov fixture at 5× through `/api/test/ibt` with the top
   screen's `/stream` and three page polls running from the pretend client; sample irdash's own CPU %, disk write
   bytes, thread count and the sizes of every file it writes once a second; ceilings while the replay says
   `SessionOn`: **no file write over 1 MB, no delete, no process scan** (count `Process.GetProcesses*` calls
   through a counter in `Proc`), irdash CPU under 3 % of one core on average, threads under 40; after the replay
   ends, the deferred jobs run and the test prints what ran and how long it waited.
