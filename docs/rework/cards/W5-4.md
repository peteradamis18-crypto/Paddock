## Lead's decisions (do not reopen)
- **No Windows scheduled task.** irdash runs all day under the logon task, so irdash's own clock starts the check at 03:00
  (`dash/src/nightly.cs`, new). CLAUDE.md rule 5 is untouched: nothing is installed or changed in Windows.
- **The check clicks nothing and never starts the sim.** PLAN's "Test Drive start/out/reset/quit loop" belongs to the deck
  journey (`tests\deck-v2-live.ps1`, run by the lead), not to the night: a sim start needs an unlocked PC and Peter away, and
  the night is when the PC is locked. So the nightly check needs only `Assert-RigFree` (the sim off, no START key in 10 min)
  plus 10 minutes with no keyboard or mouse input ([RigGuard]::IdleMinutes(), the guard's own reader); a locked PC is fine.
- **Honest words.** One line, Peter's words: "Rig check 03:00: all good" / "Rig check 03:00: 2 things: Stream Deck was not
  running (started it); the add-on is out of date" / "Rig check 03:00: skipped, Peter was at the PC" / "Rig check 03:00: did
  not finish (irdash did not answer)". Never a stack trace on RIG.

## What the check does (`tests\nightly.ps1`, new; ≤ 10 minutes, BelowNormal, dot-sources `tests\guard.ps1`, `Enter-TestLock 'nightly' 0`)
1. `irdeck-cli.exe state` answers (sim=False expected; anything else = skipped with the reason).
2. The five dry key runs that `tests\keys-test.ps1` section 8 already uses (reuse its exact commands and expected answers;
   no new commands; nothing that needs a session).
3. `GET /health`: every app it lists is `ok` or `off` for a reason the line can say; `GET /api/doctor/run?quiet=1` then the
   `doctor` headline (facts §2) after it finishes (poll `/doctor` `running` no faster than every 2 s, at most 60 s).
4. **A real Stream Deck restart** (PLAN 6 line 363; the rig is free at night): `irdeck-cli.exe` has a Stream Deck restart the
   Doctor uses (`doctor.cs FixStreamDeck`, `--runinbk`): run that path through irdash's own fix (`/api/doctor/run`), then prove
   the add-on is back: the `deck` app `ok` in `/health` within 90 s and `Showcase.DeckPollAge` under 60 s (via `/doctor` item
   `streamdeck` detail or `/deck/summary`); the deck must open on MAIN (the add-on's start page; read it from the deck summary
   if it says which page is up, else say "page not checked" in the line, never guess).
5. **One recorder minute:** if the recorder has a dry self-test today (grep `dash/src/recorder.cs` for a test or dry route
   that records one minute to the test folder without a session), run it and check a file appeared and was removed; if there is
   none, the line says "recorder: not checked" and your report says what a self-test would need. Do not invent one in this card.
6. Writes `tests\nightly.txt` (one line per night, newest last, kept 60 lines) and `tests\last\nightly-<yyyyMMdd>.txt` (the full
   log for the lead). Exit 0 always (the line carries the result); the guard's exit 3 becomes the "skipped" line.

## irdash side (`dash/src/nightly.cs`)
- At 03:00 local (once a day; also at the first tick after 03:00 if irdash was down then, before 06:00), when
  `RigState.Busy` is null and idle ≥ 10 min, start `powershell -NoProfile -ExecutionPolicy Bypass -File tests\nightly.ps1` at
  BelowNormal, hidden, 12-minute kill timeout; `Program.TestMode` instances never run it. Then read the last line of
  `tests\nightly.txt`.
- State part `nightly` (5000 ms; W5-1's contract, exactly): `{"at":"2026-11-15T03:00","text":"Rig check 03:00: all good","ok":true}`;
  no file yet → the part is `null`. `GET /api/nightly/run` (test hook only, 409 in a real session) starts it now for the lead.
- `dash/irdash.ini` key `nightly=on|off` (default on) so the lead can stop it without a rebuild.
