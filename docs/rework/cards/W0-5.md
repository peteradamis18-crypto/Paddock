## Why
The top screen makes about 16 requests a second sitting idle and 11 a second while Peter drives, the deck 2.9 a
second all day, each one a new TCP connection and a new thread on the server, `/version` walks the whole www tree
on every call, and static scripts are re-downloaded on every page open. This is the part of Paddock that runs
during races. Target ceilings: HOME idle ≤ 2/s, driving ≤ 1/s besides the stream, deck idle ≤ 0.3/s.

## What to build

1. **Server: one state push.** `GET /state` returns one JSON object with everything the 14 pollers asked for:
   kids, tow-wait, keymsg, nav sequence numbers (`/nav`, `/vault/nav`, `/perf/nav`, `/debrief/nav`), guest,
   mydrive, doctor (cached), overlays, recorder, health, showcase, rig (from `RigState`: driving, sessionOn,
   simRunning, online), version, and a `seq` that increases when anything in it changes. The same object is
   pushed as `event: state` on the existing `/stream` connection whenever `seq` changes (at most 4 times a
   second), so a page with the stream open never polls `/state`. Build it from one `StateBuilder` that each module
   feeds through a `Changed()` call (no module walks files or processes to answer it; W0-3 made those cached).
2. **Server: cheaper requests.** HTTP keep-alive (reuse the connection; the per-request thread becomes a small
   pool, `/stream` keeps its own thread); static files under `dash/www` get `Cache-Control: max-age=31536000,
   immutable` when the request carries `?v=<version>` and `no-store` otherwise; `/version` is computed once at
   start and on a `FileSystemWatcher` change, never by walking the tree per call. The reload-on-change behaviour
   the pages rely on stays exactly as it is (it postpones while driving).
3. **Web: `dash/www/app/lib/data.js`** (plain script now, module later): ONE stream connection with `event: state`
   handling, `data.state` (the latest object), `data.on('state', fn)`, `data.rig.driving` / `data.rig.online`,
   `data.json(url, ttl)` cached fetch for page data, and the one fetch helper that adds `X-Paddock: 1` (W0-2).
   Telemetry: the stream asks only for the variables the visible layout needs (`VARS` per layout; HOME idle asks
   for none) at 15 Hz, not 30; the session YAML is parsed once on the server and the fields the pages use
   (drivers, car, track, session type) ride in `state`, not the raw YAML (keep the raw YAML available on demand
   for the pages that still parse it, and list them in the report for wave 2).
4. **Web: move the 14 pollers onto it:** `keymsg.js`, `ui.js KidsMode` / `TowWait`, `pagehost.js` (`/nav` ×2,
   `/vault/nav` ×2, `/perf/nav`), `vaultlive.js`, `guest.js`, `mydrive.js`, `rig.js` (`/doctor`, `/overlays`),
   `ui.js` + `home.js` (`/health`), `intro.js` (`/showcase`), `home.js` (`/vault/recorder`), `core.js` (`/version`),
   `debrief-v4.js` (`/debrief/active`, `/debrief/nav`), `workbench.js` (`/workbench/cmd` every 300 ms → an
   `event: workbench` on the stream or `state` seq; and it stops when the page is hidden or `rig.driving`).
   The open pages' own lists (Sessions 20 s, Vault 15 s, My Races 10 s, Performance 8 s) refresh on the matching
   `seq` change instead of a timer. Pages never poll; they subscribe.
5. **Deck: `GET /deck/summary`**: one JSON with what every opener key on MAIN / MORE / LEAVE paints (showcase,
   overlays, guest, mydrive, replay, races count, workbench state, sound, ac) built from the same `StateBuilder`;
   the add-on polls it every 5 s when idle on MAIN (today 6 routes every 2 s), nothing while the Stream Deck
   page is hidden, and an open screen polls its own route at its own interval as today. `/mydrive` is no longer
   fetched for keys that are not on screen; the speed-test trigger and the auto-open flag ride in the summary.
6. **Request-rate tests** with the W0-8 pretend irdash `/__stats` and headless Chrome: HOME idle for 30 s → ≤ 2
   requests/s; HOME with `rig.driving` true for 30 s → ≤ 1/s besides the stream; Analysis open 30 s → ≤ 2/s; the
   add-on on MAIN idle 30 s → ≤ 0.3/s; a stream `state` push reaches the page within 300 ms of a `Changed()`
   (use the pretend irdash's push).
